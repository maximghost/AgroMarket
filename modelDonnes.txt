5. Stockage Cloudflare R2
Cloudflare R2
5.1 Options d'exposition des fichiers
Le dev en charge du stockage choisira l'une des trois options suivantes selon les contraintes projet :

Option
Description
Avantages
Inconvénients
A — Domaine custom(recommandé)
Lier un domaine ex: cdn.agrimarket.com au bucket R2 via Cloudflare
URLs propres, CDN gratuit, HTTPS auto, pas d'exposition du bucket R2 en clair
Nécessite un domaine et accès Cloudflare DNS
B — Domaine R2 public
Activer r2.dev sur le bucket (URLs: pub-xxx.r2.dev/...)
Simple, rapide à configurer
URLs peu lisibles, pas de domaine custom
C — URLs signées
Fichiers privés, génération d'URLs temporaires côté backend
Contrôle d'accès fin
Complexité accrue, URLs expirent


⚠ L'option A (domaine custom) est recommandée pour la production. L'option B peut être utilisée pour le dev/staging.

6. Intégration KKiaPay
KKiaPay est le prestataire de paiement mobile money (MTN, Moov, Wave…). L'intégration combine le widget frontend et la vérification backend via webhook.
6.1 Flux de paiement complet

1. Client POST /orders  →  Commande créée (payment_status: "unpaid")
2. Backend retourne { order_id, total_amount }
3. Frontend ouvre le widget KKiaPay avec { amount, api_key, order_id }
4. Client paie via mobile money
5. KKiaPay appelle le webhook backend POST /payments/kkiapay/webhook
6. Backend vérifie la transaction via l'API KKiaPay (verifyTransaction)
7. Si vérifiée → Order.payment_status = "paid", Order.status = "confirmed"
8. Backend retourne HTTP 200 à KKiaPay

⚠ Ne jamais marquer une commande comme payée sans avoir vérifié côté backend via l'API KKiaPay. Le callback frontend seul n'est pas suffisant.
6.2 Variables d'environnement

KKIAPAY_API_KEY=xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx   # Clé publique (widget)
KKIAPAY_PRIVATE_KEY=xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx  # Clé privée (webhook)
KKIAPAY_SECRET=xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx        # Secret HMAC (signature webhook)
KKIAPAY_SANDBOX=true   # false en production
6.3 Intégration widget frontend

// Charger le SDK KKiaPay
<script src="https://cdn.kkiapay.me/k.js"></script>


// Ouvrir le widget après création de la commande
openKkiapayWidget({
  amount: order.total_amount,
  api_key: process.env.KKIAPAY_API_KEY,
  callback: "https://monapp.com/payment/return",
  data: order._id,          // order_id passé en metadata
  theme: "#1F4E79",
  sandbox: true,
});


// Écouter la confirmation côté client (UI seulement — ne pas se fier pour la logique métier)
addSuccessListener(function(response) {
  // response.transactionId disponible
  // Afficher un message de succès, rediriger vers /orders/:id
  // La vérification réelle est faite par le webhook backend
});
6.4 Webhook backend
Route

Méthode
Endpoint
Auth
Description
POST
/payments/kkiapay/webhook
Signature HMAC
Callback KKiaPay — confirmation de paiement


Payload reçu
{
  "transactionId": "TXN_XXXXXXXX",
  "status": "SUCCESS",
  "amount": 15000,
  "data": "ORDER_OBJECTID"   // order_id passé en metadata widget
}

Logique de traitement (pseudo-code)
// 1. Vérifier la signature HMAC
verifyWebhookSignature(req.headers['x-kkiapay-signature'], req.body, KKIAPAY_SECRET)


// 2. Vérifier la transaction auprès de l'API KKiaPay
const tx = await kkiapay.verifyTransaction(transactionId)
if (tx.status !== 'SUCCESS') return res.status(200).end()


// 3. Retrouver la commande
const order = await Order.findById(data)
if (!order || order.payment_status === 'paid') return res.status(200).end()


// 4. Vérifier le montant
if (tx.amount !== order.total_amount) { /* log anomalie */ return res.status(200).end() }


// 5. Mettre à jour la commande
order.payment_status = 'paid'
order.status = 'confirmed'
order.kkiapay_transaction_id = transactionId
await order.save()


// 6. Répondre 200 à KKiaPay (obligatoire)
return res.status(200).json({ received: true })


6.5 Gestion des cas d'échec

Scénario
Action
Widget fermé sans payer
Commande reste pending — annulation auto après X minutes (cron job V2)
Webhook reçu mais signature invalide
Rejeter (HTTP 400), logger l'alerte sécurité
Montant webhook ≠ montant commande
Logger anomalie, NE PAS marquer comme payé, alerter admin
Webhook reçu en double
Vérifier order.payment_status avant maj (idempotence)
Paiement échoué (status FAILED)
Mettre payment_status = "failed", notifier le client
